## 🚀 当前能力与启动

`rto-chat`和`python -m petroleum_rto.domain_model`装配同一个`ReactAgent`。单一官方`create_agent`图保留原始消息与会话状态，支持一般对话、工艺问答、装置身份、当前HYSYS工况及已有结果查询；模型工具负责查询、准备、修改和取消，真实用户确认后由固定节点完成基准与选定MV候选的稳态比较。当前会话保存到本机SQLite，模型正文可在交互终端逐片显示；旧对话按容量摘要，大工具结果可在重启后继续分页读取。

当前Windows开发目录为`D:\pyproject\petroleum_rto_agent`，开发分支为`feat/react-agent`。本机项目依赖已安装，使用项目Python启动：

```powershell
Set-Location D:\pyproject\petroleum_rto_agent
.\.venv\python.exe -m petroleum_rto.domain_model
```

当前`.venv`采用Conda目录结构，安装流程见[根README](../../README.md)。全新标准环境可使用`uv sync --locked --extra domain-model --group dev`；标准Windows解释器在`.venv/Scripts/python.exe`，POSIX在`.venv/bin/python`，都可使用同一模块入口。

本机凭据固定为`src/petroleum_rto/domain_model/dmx_api.json`，不纳入Git，也不从历史机器自动迁移。可以是一行密钥或只含`api_key`的JSON；读取器拒绝宽松权限、链接、重复键及超限文件。Windows要求当前用户拥有文件，DACL仅允许该用户及系统/管理员等受支持主体；读取时只校验，不修改已有凭据权限。没有配置时启动明确报错。

`chat_settings.py`中的启动模型、Chat端点和附加角色说明仍生效；新会话默认使用`gpt-5.6-sol-cdx`，已有会话恢复其保存的模型与思考选择。切换已有会话可输入`/model 3`，这不会清除历史或任务。传输从Chat端点确定API根地址，再按所选模型调用Chat或Responses。`domain-model`可选依赖包含LangChain、httpx和官方`langgraph-checkpoint-sqlite`；后者要求的aiosqlite/sqlite-vec随锁文件安装，本项目不启用向量扩展。稳态运行时和仿真模块不依赖框架或会话数据库。

实际CLI在`runs/assistant/steady-session.sqlite`保存当前会话，持有本机独占锁直到关闭；另一个CLI同时打开会明确失败。POSIX使用0600文件权限和flock；Windows使用本机字节锁、私有DACL、拒绝重解析点/硬链接并持有目录句柄防止路径替换。新建Windows会话目录限制访问，已有目录只验证，不自动改权限。损坏/不支持版本拒绝读取；只保存严格JSON及白名单框架类型，不使用pickle回退，不保存凭据或HTTP客户端。首次启用从新会话开始，不能恢复旧进程尚未持久化的内存。

## 当前工况查询

read_operating_context的工具合同5.0.0返回同次观测的readings：变量标识、对象、属性、量纲、单位及数值，包括进料温度/压力/流量、注水、五条产品流量、TBP点及其他已绑定读数。同时返回control_values，提供24项MV的当前值、单位及可修改标志；CV也可读取，但不进入写入请求。完整快照仍在本地，路径、磁盘哈希、内部值及塔板明细不进入该摘要。

TBP为沸点曲线温度，不能当作出口温度；物流总量不表示合格成品产量。该工具不额外读取组分/相态或全物料能量边界，不应宣称这些数据已获取。查询不写入或调用求解器，保留本次时间和快照引用；方案、结果与会话格式不变。

## 💬 终端命令

交互输入使用Python的input。POSIX使用readline支持中文退格、左右移动及行尾Ctrl-U清空；缺少readline时明确提示退出。Windows使用原生控制台编辑，不要求安装readline，快捷键依宿主终端，不承诺Ctrl-U与POSIX相同。输入阶段Ctrl-C退出，空行不退出。文件或管道仍按行读取，多行文本逐行提交。自动化验证范围与尚未完成的人工中文输入检查见STATUS。

请求运行期间，Windows原生Ctrl-C回调先通知框架停止后续工作，再交给Python默认中断处理；运行结束移除回调并恢复原处理器，调用方自定义SIGINT时不替换。它用于阻止中断后的额外重试，不保证立即终止当前HTTP或底层计算。下一轮使用新的运行控制。

| 命令 | 当前行为 |
| --- | --- |
| `/model` | 显示当前模型和列表；随后可直接回复编号或完整ID选择，输入0退出选择 |
| `/model 2`或`/model kimi-k3` | 切换精确模型，保留会话、快照和最近结果，不触发请求 |
| `/thinking` | 查看当前模型思考设置 |
| `/thinking on high` | 设置当前模型支持的思考模式和强度；Flash渠道拒绝开启，非法强度拒绝 |
| `/thinking off`或`/thinking default` | 关闭或恢复该模型默认；常开模型拒绝关闭 |
| `/capabilities` | 本地读取装置与能力，展示结果并加入后续上下文 |
| `/result [workflow_id]` | 查看受控结果编号或当前会话已有结果；不接收任意路径 |
| `/confirm` | 本地确认已展示的当前版本，通过公共审批节点执行稳态比较；已完成时校验已有证据并展示结果 |
| `/resume` | 恢复已批准但未完成的任务；先展示恢复摘要，不批准新方案，不因普通追问续算 |
| `/cancel` | 取消后续执行，保留已有结果 |
| `/clear` | 清除会话、摘要、分页原文、方案、快照和最近结果，保留模型选择及磁盘结果 |
| `/help`、`/exit` | 查看包含当前模型/思考/待办的帮助、退出并关闭HTTP/SQLite资源及会话锁 |

自然语言询问“你能做什么”“当前用哪个模型”“怎么改思考设置”仍由同一个Agent回答。每次请求都附加与`/help`同源的命令说明、模型菜单、当前思考及任务状态，不依赖旧摘要记住应用用法。切换模型、修改思考或取消方案后立即重建该视图；没有方案也明确传递空状态，旧历史不能恢复确认资格。应用帮助本身不读取装置配置，目标和变量的实际能力仍由`/capabilities`或领域工具提供；模型不能通过回答自行切换设置。

普通输入不进入固定意图分类。只有无参数`/model`开启一次模型选择：下一条编号或精确ID在本地处理，成功后关闭；无效编号提示重试，空行保留选择状态。输入0退出选择；普通自然语言退出选择并正常聊天，其他斜杠命令退出选择并执行原有功能（`/cancel`仍取消优化方案）。未打开选择时，单独数字保持普通聊天；`/thinking`或切换完成后的列表展示不会重新开启选择。正在执行的一轮不能换模型。

默认CLI执行期间按Ctrl-C会请求停止当轮：普通模型和摘要都不会再发起后续HTTP尝试，也不会执行中断请求返回的新工具；已完成查询保留，返回输入后可以继续。仍可能需要等待当前HTTP请求、重试退避或工具调用结束，不承诺立即终止底层计算。每次图运行使用独立的官方`RunControl`，回调异常退出也会先请求停止再关闭；运行结束后恢复原信号处理器，不覆盖嵌入调用方的自定义SIGINT处理。这些控制不写入会话，也不改变后续明确恢复任务的规则。

切换至Flash时固定关闭思考，切换其他模型时默认开启；不继承前一模型的思考设置。Flash的`/thinking on`直接说明当前渠道仅使用非思考模式，不发送请求、不改会话或方案。其余模型仍支持各自合法设置，Kimi不能关闭思考。

交互终端显示读取、准备、保存基准副本、基准计算、候选计算与结果保存进度。完整证据重载会注明未重新计算，进度不进入模型对话，不代替持久化物理证据。

输入编辑期间不后台刷新；管道/重定向继续保留按行输入和最终结果输出，不显示交互进度或终端控制序列。交互终端消费标准消息片段显示模型正文，程序进度、摘要响应与原始推理不混入正文，最终输出不重复打印已显示内容；文字显示后若失败，会明确标记本次回答不完整。

当前模型遇到可恢复的网络、限流或服务错误时，普通请求最多尝试3次，不自动换模型。若上次已显示文字，重试前会说明回答未完整生成并标明第2/3次尝试，随后显示重新生成的正文；失败片段不会拼入保存的成功回答。只接收正文回调的客户端也有明确程序分隔。三次仍失败时报告实际尝试次数和安全错误原因，已完成查询、方案和结果保留，不把错误伪装成模型答复。认证、权限、解析或已收完传输但协议不完整等永久错误直接停止；未完整接收的工具调用不执行。

## 🔧 MV稳态比较与恢复

工具合同5.0.0保留五个领域工具名称，准备参数为snapshot_ref、changes和可选previous_plan_ref。changes含1至24项，每项只允许variable_id、value、unit；能力工具返回[变量目录](../../configs/simulation/mjh_atm_variables.json)内24项MV及单位，重复标识、CV、未知变量、错误单位和非有限值明确拒绝。只采用量纲定义检查（如非负流量、百分数0至100），这些不构成工艺有效范围；不接受旧objectives、decision_variables、max_candidates或任意constraints，不运行旧网格搜索或动态复核。

1. 模型读取能力和已打开HYSYS的当前工况，再准备比较方案。准备只绑定受信观测、选定MV目标、变量目录和边界定义哈希，不计算。
2. 程序展示方案后，下一轮整条输入/confirm、确认或确认执行，经公共审批节点授权。修改必须引用当前版本并重新展示；修改失败也撤销旧确认资格。
3. 单一SteadyComparison节点保存基准副本，校验源观测仍与准备时一致；分别在独立工作案例重算基准和候选，保存各自计算后的物料、组分及能量边界。
4. 程序从严格重载的证据计算差值并展示，再由当前模型补充说明。重复性尚未通过，结果只能是comparison_only或evaluation_error，不进行最优排名、产品放行或收益判断。

“保存基准副本”与“暂停计算”是两个动作。原hysys_control.py的suspend/resume通过Solver.CanSolve关闭/开启求解；正式单点使用同样开关，在拥有的工作案例中预检所有选定MV，暂停后批量写入并读回，最后统一Reset/Run；发生部分写入失败时不求解部分方案，关闭该工作案例并从基准恢复。活动塔规格写GoalValue，其他MV写ImportedVariable.SetValue，流量按kg/h与内部kg/s换算。

会话合同升级为2.0.0，删除static中间槽位；默认新会话库保留旧session.sqlite原件，不自动迁移旧方案授权。重启只恢复及核验，不连接HYSYS或请求模型。明确/resume可续接尚未开始的计算；已存在且完整的基准/候选证据只读复用，部分目录或损坏证据明确拒绝，不覆写、不自动重试。当前Agent对同项目HYSYS读写使用现有文件锁串行化，直接调用底层接口仍由调用方保证串行。

结果展示每个选定MV的基准与候选目标、读回值及实际值、九物流总量及能量输入/输出/余额的差值，同时保留限制。常规数值两位小数，小非零变化保留必要精度，物理证据不舍入。总物流不是合格成品收率，能量边界不是燃料费用。结果说明失败不撤销已完成计算；/result及重复确认只核验并展示，不再次请求模型。

重复强调变量排除时，即使方案已有同样范围，也要求模型重新准备并由程序展示完整范围。新方案等待本轮结束后展示，随后才接受下一轮确认；这不叫“方案失效”。程序用简短状态提示说明下一步。

待确认时聊天、查询和切换模型保留当前方案，不再依赖keep工具。进入修改路径即撤销旧资格，参数或业务校验失败后仍须重新准备并展示；取消后旧动作不能复活。改变方案的工具调用必须独占一条模型响应，混排批次在执行前拒绝；领域工具保持串行。

确认规则只忽略首尾空白，不忽略标点、引用及附加条件。程序从实际当前用户输入判断，模型没有确认工具，也不能截取或复述“确认”来授权。“同意”“确认？”及“确认但只调温度”均不能授权；其他自然语言仍走统一工具循环，没有独立意图分类器。

若DeepSeek Pro思考模式的历史回复缺少必需推理字段，下一次带工具请求会在发送前停止并提示；可以显式`/thinking off`或切换模型后继续，历史转为背景数据，方案与结果保留。Flash仅使用已验证的非思考模式，停止适配该渠道的思考续接；这不代表原厂Flash不支持思考。

重启会恢复原始消息、模型/思考选择、快照、固定方案、审批与阶段状态、摘要和分页，但只展示恢复摘要，不请求模型或运行计算。待审批方案仍须确认；已批准未完成方案必须在展示后明确输入`/resume`，普通追问不续算。`/cancel`取消任务并保留已有结果；`/clear`清除当前会话全部可恢复记录和授权，保留模型选择与磁盘RTO证据。

固定方案保存完整受信观测、选定MV目标、变量目录与边界定义哈希，读取时严格校验其版本和指纹。已完成结果及取消后保留的最近结果在恢复时从磁盘重新构建，缺失或损坏明确失败。完整单点不重新求解，尚未创建的下一步骤可在明确/resume后继续；不完整目录不会被覆写。旧static槽位和物理M2/M4计数字段已移除。

### Responses统一迁移实测（2026-09-09）

2026-09-09的历史探针使用合成标记测试五个精确型号的标准Responses输入、SSE及两次依赖工具调用。GPT CDX与Flash非思考通过生产解析器和完整往返。Qwen、Pro在诊断路径原样续传其返回项后完成往返，但reasoning没有非空encrypted_content，面向GPT的生产Responses解析器拒绝；这是适配差异，不能据此声称模型不支持Responses。Kimi对字符串及标准消息数组均报400 messages must not be empty；对合法函数名read_marker和lookup报400 function name is invalid，未通过工具接口。因此“全部通过后统一”的条件未满足，协议映射保持，未增加Chat回退或伪造推理字段。该次未验证全强度、长上下文或内置搜索。

## 🧩 模块与消息

- [native.py](../../src/petroleum_rto/domain_model/native.py)适配LangChain模型，使用httpx直接保留完整Chat assistant或Responses output。现成循环由LangChain提供，不自行解析文本工具计划。
- [react.py](../../src/petroleum_rto/assistant/react.py)装配单一create_agent图及公共审批/稳态比较中间件节点，管理本地命令、恢复、普通模型有限重试与正文/进度显示；原始messages和session是唯一活动状态。
- [presentation.py](../../src/petroleum_rto/assistant/presentation.py)将严格读取的结果回执转换为可读方案，仅处理显示精度，不修改机器合同或计算值。
- [state.py](../../src/petroleum_rto/assistant/state.py)定义严格版本化会话、模型选择及上下文恢复；[session.py](../../src/petroleum_rto/assistant/session.py)管理官方SqliteSaver、严格JSON、单会话互斥和关闭。
- [native_tools.py](../../src/petroleum_rto/assistant/native_tools.py)提供五个无独立活动状态的领域工具，参数模型生成Schema并严格校验，状态从ToolRuntime传入并通过Command更新。
- [context.py](../../src/petroleum_rto/assistant/context.py)根据图状态重建发送视图与原文覆盖关联，提供第六个工具`read_tool_result`；通过官方`SummarizationMiddleware.before_model`公共接口逐批摘要，有效批次先保存检查点。每次模型调用前投影当前方案，摘要不能授权，原始messages始终完整保留。
- [models.py](../../src/petroleum_rto/domain_model/models.py)提供精确ID与实际请求参数；请求模型和服务端声明模型分别记录，后者不等于独立身份认证。

Chat响应允许无正文的工具调用。完整调用ID、名称、JSON参数和推理字段保留，下次附带对应tool结果。Responses完整保留函数调用、消息和加密推理项，回传function_call_output；不依赖previous_response_id或跨模型响应链。

`_stream`提供标准`ChatGenerationChunk`/`AIMessageChunk`，`_generate`聚合同一路径；正文可逐片显示，完整工具调用和原生推理状态只在严格结束校验后提交一次。Chat参数增量按索引拼接，Responses核对completed事件与完整output；截断、重复JSON键、非法类型、缺少必要推理或错误结束原因都会停止，不执行不完整参数。`usage_metadata`只映射实际返回的完整用量，缺失不伪造；实际外发计数在传输边界累计。关闭推理显示不会删除必要续接状态。

## 🗂️ 容量与保留

完整原始记录由图和本机SQLite保存，发送视图按当前模型重建。切模型时旧对话/工具结果作为有来源的背景数据进入新上下文段；不伪造新模型的assistant推理，不丢快照引用。没有64条消息提交上限，也没有第二套活动历史。

当前使用保守UTF-8字节估计加协议余量，包含工具Schema和推理状态；再预留应用生成预算。该估计可能比真实token数量大，不是精确tokenizer。GPT Sol CDX采用用户指定的256K应用上下文预算，其他模型保留既有预算；按预算自动摘要和检查超限，不再存在未知容量禁止请求路径。

接近容量时，系统通过官方摘要组件的公共钩子，使用当前模型分批摘要较早的完整交互。公开`keep`参数决定保留量，实际工具组切点由组件处理；当前输入和本轮工具交互不参与摘要。`trim_tokens_to_summarize=None`关闭摘要前预裁剪，过大历史通过缩小每批较旧前缀处理，原始记录不删除。官方消息更新只应用到一次性发送视图，不改写图中的原始messages。

每批摘要必须非空、无工具调用，并让完整协议载荷变小，才提交摘要及原文覆盖关系；有效批次先保存检查点，再继续下一批。后续失败不会覆盖此前摘要，失败批次的预算消耗也会保存。`covered_until`仅从官方返回的保留后缀推导，用于关联已归档原文；已删除私有切点调用和摘要模型改写。摘要不能恢复确认资格，终端只提示已生成摘要，摘要响应不混入模型正文。

大工具结果以明确的全文引用替代发送内容，`read_tool_result`按字符偏移分页，不重做原计算；全文引用及原文可跨进程恢复。切换模型保留摘要及原文关联，旧模型推理字段不跨模型发送；重启恢复原始消息、有效摘要、分页和方案，启动仍零模型请求、零计算。`/clear`删除摘要和分页原文；没有历史会话列表、自动淘汰或无限容量承诺。单条不可拆分历史、当前输入/工具批次或必需任务状态仍超限时停止并保留记录。完整流程见[架构说明](../architecture/02_领域智能体架构与功能设计.md)。

每轮模型调用次数是循环资源预算，与窗口和历史轮数不同。普通模型通过官方`ModelRetryMiddleware`只重试结构化临时错误，循环和退避由框架处理；公共包装只观察真正开始的尝试。上下文先生成发送视图，普通请求重试不重跑摘要或已完成工具。摘要另有每轮逻辑批次预算，复用相同上限值，不占用Agent循环次数；摘要模型通过公开`with_retry`执行自己的有限重试，不再叠加普通模型中间件。永久错误、解析错误、空摘要或工具调用响应不重试；达到预算、摘要无效或不缩小载荷时停止，保留原文与已提交摘要。

普通逻辑调用与摘要逻辑批次各自最多`max_model_calls`次，两条路径共用每次最多3次尝试的常量，因此每轮普通与摘要HTTP尝试分别不超过逻辑上限的3倍，合计不超过`6 * max_model_calls`。上限由现有预算推导，没有新增独立配置或重复计数器。传输的`request_count`在实际外发边界核对所有尝试，发送前的容量调整不产生HTTP尝试。HTTP超时及响应字节保护独立于上下文，响应上限按本次生成预算计算。自动换模型关闭，也不加载外部追踪配置。
