## 💬 终端命令

| 命令 | 当前行为 |
| --- | --- |
| `/model` | 显示当前模型和列表；随后可直接回复编号或完整ID选择，输入0退出选择 |
| `/model 2`或`/model kimi-k3` | 切换精确模型，保留会话、快照和最近结果，不触发请求 |
| `/thinking` | 查看当前模型思考设置 |
| `/thinking on high` | 设置当前模型支持的思考模式和强度；Flash渠道拒绝开启，非法强度拒绝 |
| `/thinking off`或`/thinking default` | 关闭或恢复该模型默认；常开模型拒绝关闭 |
| `/capabilities` | 本地读取装置与能力，展示结果并加入后续上下文 |
| `/result [workflow_id]` | 查看受控结果编号或当前会话已有结果；不接收任意路径 |
| `/confirm` | 确认已展示的当前版本并顺序执行M2/M4；已完成时直接展示结果 |
| `/cancel` | 取消后续执行，保留已有结果 |
| `/clear` | 清除会话、摘要、分页原文、方案、快照和最近结果，保留模型选择及磁盘结果 |
| `/help`、`/exit` | 查看帮助、退出并关闭HTTP资源 |

普通输入不进入固定意图分类。只有无参数`/model`开启一次模型选择：下一条编号或精确ID在本地处理，成功后关闭；无效编号提示重试，空行保留选择状态。输入0退出选择；普通自然语言退出选择并正常聊天，其他斜杠命令退出选择并执行原有功能（`/cancel`仍取消优化方案）。未打开选择时，单独数字保持普通聊天；`/thinking`或切换完成后的列表展示不会重新开启选择。正在执行的一轮不能换模型；Ctrl-C中止当轮并保留已完成查询，之后可以继续输入。

切换至Flash时固定关闭思考，切换其他模型时默认开启；不继承前一模型的思考设置。Flash的`/thinking on`直接说明当前渠道仅使用非思考模式，不发送请求、不改会话或方案。其余模型仍支持各自合法设置，Kimi不能关闭思考。

## 🔧 优化交互与恢复

1. 直接描述目标和可调变量。模型先读取能力与工况，用`prepare_optimization`确定性构造问题，程序展示目标、变量范围、约束、工况时间与执行范围；此时没有仿真。
2. 回复“只调温度，不调压力”等修改，模型重新准备方案并产生新版本。旧版本立即失去确认资格；修改失败也不能裸确认旧方案。
3. 在后续用户轮确认。`/confirm`由程序直接处理；整句“确认”“确认执行”仍由同一模型通过`manage_optimization`处理，程序校验允许的完整输入、当前轮次和已展示版本。
4. `solve_optimization`完成全部静态搜索和配对评价，`verify_optimization`复核完整入围列表并最终选择。程序单独展示已核验的关键结果，即使模型解释失败也保留结果。

重复强调变量排除时，即使方案已有同样范围，也要求模型重新准备并由程序展示完整范围。新方案等待本轮结束后展示，随后才接受下一轮确认；这不叫“方案失效”。程序用简短状态提示说明下一步。

待确认时仍可聊天、查询和切换模型。模型明确判断不改方案时调用`manage_optimization keep`；未处理清楚的输入、工具或协议失败暂停确认资格，需要澄清并重新准备展示。`keep`不能恢复此前已暂停的资格，也不能绕过本轮修改。改变任务或执行计算的调用必须逐个进行；混排批次在执行前整体拒绝。

执行确认合同2.1.0沿用2.0.0的输入规则：只接受整条输入`/confirm`、`确认`或`确认执行`，仅忽略首尾空白；标点、引用及附加条件不被忽略。程序从实际当前用户输入判断，模型不能截取“确认”来绕过检查。非允许输入误发confirm时返回`confirmation-input-required`并暂停资格；模型处理需求、重新准备展示后，等待下一轮确认。“同意”“确认？”及“确认但只调温度”均不能授权；其他自然语言仍走统一工具循环，没有恢复独立意图分类器。

若DeepSeek Pro思考模式的历史回复缺少必需推理字段，下一次带工具请求会在发送前停止并提示；可以显式`/thinking off`或切换模型后继续，历史转为背景数据，方案与结果保留。Flash仅使用已验证的非思考模式，停止适配该渠道的思考续接；这不代表原厂Flash不支持思考。

会话和确认状态仅在当前进程内。重启后不会恢复授权；重新读取/准备/展示/确认同一问题后，可以校验已有v4阶段文件并继续，不重做已完成的阶段。半个阶段中断仍沿用原编排的恢复语义，不保证每个候选在崩溃后恰好执行一次。`/result <workflow_id>`严格重载证据；只有M2的运行不是完整结果，当前会话可查询其阶段状态。

## 🧩 模块与消息

- [native.py](../../src/petroleum_rto/domain_model/native.py)适配LangChain模型，使用httpx直接保留完整Chat assistant或Responses output。现成循环由LangChain提供，不自行解析文本工具计划。
- [react.py](../../src/petroleum_rto/assistant/react.py)保存共同记录，逐个收集已完成模型/工具节点；解释失败不丢已返回工具结果。
- [native_tools.py](../../src/petroleum_rto/assistant/native_tools.py)提供七个领域工具，Schema由参数模型生成并校验；Context、Problem及确认资格留在程序中。
- [context.py](../../src/petroleum_rto/assistant/context.py)复用LangChain摘要组件，管理发送视图与覆盖水位，提供第八个原生工具`read_tool_result`。每次模型调用前重新投影当前方案，摘要不具有执行授权。
- [models.py](../../src/petroleum_rto/domain_model/models.py)提供精确ID与实际请求参数；请求模型和服务端声明模型分别记录，后者不等于独立身份认证。

Chat响应允许无正文的工具调用。完整调用ID、名称、JSON参数和推理字段保留，下次附带对应tool结果。Responses完整保留函数调用、消息和加密推理项，回传function_call_output；不依赖previous_response_id或跨模型响应链。

传输使用SSE，但当前终端在完整响应校验后显示正文；目前不逐字展示输出。Chat参数增量按索引拼接并等待正常结束；Responses等待completed事件及完整output。截断、重复JSON键、非法调用类型、缺少必要推理或错误结束原因都会停止，不执行不完整参数。关闭推理显示不会删除必要的续接状态。

## 🗂️ 容量与保留

完整记录保存在进程内，发送视图按当前模型重建。切模型时旧对话/工具结果作为有来源的背景数据进入新上下文段；不伪造新模型的assistant推理，不丢快照引用。没有64条消息提交上限。

当前使用保守UTF-8字节估计加协议余量，包含工具Schema和推理状态；再预留应用生成预算。该估计可能比真实token数量大，不是精确tokenizer。原厂容量不是DMX容量证明；未知容量阻止请求。

接近容量时，系统使用当前模型分批摘要较早的完整交互；摘要覆盖的原文不再重复发送，近期工具调用/结果及必要推理关联保留，当前输入和本轮工具交互不摘要。组件默认输入裁剪和重试已关闭，不能通过摘要自动恢复方案确认资格。终端会提示已生成摘要，原始消息仍保存在进程内。

大工具结果以明确的全文引用替代发送内容，模型可调用`read_tool_result`按字符偏移分页，查询不会重做原计算。切换模型保留摘要及其水位，旧模型推理字段不跨模型发送。`/clear`清除摘要和分页原文；没有磁盘会话恢复、自动淘汰或无限容量承诺。单条不可拆分历史、当前输入/工具批次或必需任务状态仍超限时停止，并保留记录。完整流程见[架构说明](../architecture/02_领域智能体架构与功能设计.md)。

每轮最多模型调用次数是循环资源预算，与模型窗口和历史轮数不同。摘要另有每轮调用预算，复用相同上限值，并不占用Agent循环次数；达到摘要上限、摘要不缩小载荷或摘要无效时停止，原始记录与此前成功摘要保留。HTTP超时及响应字节保护独立于上下文：响应上限按本次生成预算计算。没有自动重试或自动换模型，也不加载外部追踪配置。
