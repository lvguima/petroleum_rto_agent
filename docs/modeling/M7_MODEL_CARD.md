# CDU Mini Loop M7 模型卡

> 文档状态：M7基础、M7.1受控输入及M7.2稀疏JSON/单命令确认均已完成并签署。本模型卡描述2026-08-18发布包；
> 完成不提升现场可信度，仍须结合[当前实施状态](STATUS.md)和
> [M7 发布检查清单](M7_RELEASE_CHECKLIST.md)中的限制使用。

## 1. 模型身份与目的

CDU Mini Loop 是一个常压原油蒸馏装置的缩减阶、确定性工程仿真模型。它把已经验收的
M2 稳态物理循环、M3 开环动态、M4 七回路合成 PI 闭环和 M6 工程验证场景封装到统一运行接口中，
用于以下工作：

- 演示常压蒸馏主要物料、热量、回流和循环取热关系；
- 在约定的局部适用域内比较基准、进料阶跃和选定异常场景的方向性响应；
- 检查模型内部的总质量、逐组分、盐及设备边界守恒；
- 为后续校准、验证和软件交付提供可重复、可追溯的工程基线；
- 教学、离线分析、测试和方案讨论。

它不是经过现场认证的数字孪生、控制器整定工具、软测量产品或安全系统。

## 2. 模型层级

| 层级 | 当前模型内容 | 主要输出 | 不能据此声称 |
| --- | --- | --- | --- |
| M1 | 脱盐、闪蒸、预热、炉、常压塔、冷凝与产品分离的稳态设备链 | 流股、热负荷、产品与设备守恒 | 现场稳态精度已经验证 |
| M2 | 塔顶回流及三路循环取热的稳态迭代闭合 | 收敛状态、循环物流、完整流程守恒 | 真实设备内部所有水力学细节已复刻 |
| M3 | 54 维集中参数动态状态、执行机构/传感器一阶响应、事件感知固定步长 RK4 | 开环时间序列、累计与瞬时守恒、产品观察量 | 现场动态时间常数或阀门响应已标定 |
| M4 | 七路归一化数字 PI、炉温前馈、限幅/限速与合成验收门禁 | 闭环轨迹、逐回路诊断和性能指标 | 可直接用于现场控制器整定或投用 |
| M5 | `case_20260604` 的弱时间对齐、净边界协调和两个切割温度校正 | 单案例有效模型/案例覆盖层 | 跨原油、跨工况或动态现场验证 |
| M6 | 适用域、局部工程不确定度、正常/受限/拒绝场景及模型内保护逻辑 | 场景状态、工程包络、保护和跟踪证据 | 现场 SIS 设计、验证或安全完整性证明 |
| M7 | 统一请求/结果、固定预设、包内资源、运行目录和发布门禁 | 可安装、可追溯的运行包 | 自动获得生产使用许可 |

更完整的建模路线见[实施方案](01_CDU_Mini_Loop实施方案.md)。

## 3. 统一运行类型与结果状态

M7 只接受四类运行：

| `run_type` | 对应层 | 含义 |
| --- | --- | --- |
| `steady_recycle` | M2 | 求解含回流和循环取热的稳态物理循环 |
| `open_loop_dynamic` | M3 | 执行版本化开环动态场景 |
| `closed_loop_dynamic` | M4 | 执行七回路 PI 合成闭环场景 |
| `validation_scenario` | M6 | 执行一个包内选定 M6 场景或求解前结构拒绝 |

公共结果只使用五种状态：

| `runtime_status` | 解释 |
| --- | --- |
| `success` | 数值执行以及该层要求的验收检查均通过 |
| `limited` | 场景执行通过，但只在明确标识的受限或代理适用域内解释 |
| `rejected` | 输入在求解前被结构性拒绝；不是数值收敛失败 |
| `not_converged` | 稳态或数值迭代未收敛 |
| `failed` | 执行、守恒、结果契约、写出或重载失败 |

`runtime_status` 不会覆盖底层状态。结果和 manifest 同时保留 `engine_status`；manifest 还保留
`domain_status`（`not_applicable|passed|limited|rejected`）以区分公共执行状态与适用域状态。失败阶段、
失败原因、失败时刻、结构化错误和最后有效证据也会保留。

## 4. 固定复现预设

当前注册表固定五个 ID，不扫描任意目录：

| 预设 ID | 运行类型 | 用途与范围 |
| --- | --- | --- |
| `steady-baseline` | `steady_recycle` | M5 有效基准上的 M2 稳态循环 |
| `open-loop-feed-step` | `open_loop_dynamic` | M3 进料流量 `+5%`、2 h、1 s 步长开环场景 |
| `closed-loop-feed-step` | `closed_loop_dynamic` | M4 进料设定值 `+5%`、2 h、1 s 步长闭环场景 |
| `m6-abnormal-pump-trip` | `validation_scenario` | 包内 M6 一中循环泵停运选定场景的便携复现；不是重新执行完整 M6 矩阵 |
| `m6-structural-rejection` | `validation_scenario` | 不支持汽提蒸汽输入的求解前结构拒绝演示 |

仓库状态记录显示这五个预设已经通过统一 `run()` 入口执行、完整运行目录发布和
`read_run()` 严格重载，正式执行性能、完整 2 h artifact I/O 基线及隔离wheel/仓库外3.12安装也已通过；
M7基础发布的全仓库回归和独立终验也已完成。

### 4.1 受控自定义输入

前三个模型预设还可以作为模板创建新请求。请求JSON只写关心的白名单字段，未写内容继承preset；
公开白名单覆盖进料和工况、两个切割点、动态时间常数、三个质量库存初值及M3/M4事件，运行时不会
接受任意配置路径或原始54维状态修改。普通CLI会在同一`run --request`命令中展示解析后完整输入，
确认后才运行；脚本化调用继续显式提交预览指纹。这一机制只改变运行接口灵活性，不改变M2/M3/M4
方程、六伪组分结构或既有结果契约。

## 5. 数据、伪组分与参数来源

### 5.1 六个烃类伪组分

原油被简化为六个烃类伪组分，另设水组分。六个烃类的物性来源均为缩减模型初始假设，
可信度为 `low`：

| 伪组分 | 代表范围 | 当前可信度 |
| --- | --- | --- |
| `light_ends` | 轻端 | 低 |
| `naphtha` | 石脑油范围 | 低 |
| `kerosene` | 煤油范围 | 低 |
| `light_diesel` | 轻柴油范围 | 低 |
| `heavy_diesel` | 重柴油范围 | 低 |
| `residue` | 重端/渣油范围 | 低 |

`water` 使用标准水物性初值，目录可信度为 `medium`；这不会提升六个烃类伪组分或整个模型的
总体可信度。现有原油化验馏程不完整且时间错位，M5 没有重新拟合六伪组分。产品质量代理因此只能
用于方向性观察，不能当作现场化验预测。

### 5.2 M5 单案例覆盖层

默认运行不是直接修改基础 JSON，而是加载基础模型、基础案例和组分目录后，再应用严格白名单的
M5 覆盖层：

- 闪蒸温度：`493.15 K → 473.75 K`，属于弱时间对齐的案例输入修订；
- 洗水比：`0.04 → 0.04654072620215898`，属于弱时间对齐的案例操作量修订；
- 第三个塔切割点：`583.15 K → 571.7046875 K`，属于 M5 校正参数；
- 第四个塔切割点：`638.15 K → 647.9546875 K`，属于 M5 校正参数。

M5 只校正了一个案例中的两个切割温度，声明范围固定为 `case_alignment_only`。闪蒸温度和洗水比
来自弱时间对齐案例信息，不是额外的已辨识设备参数。其余伪组分物性、设备参数、动态时间常数和
控制参数没有因 M5 而升级可信度。

### 5.3 来源分层

- `base_files/` 中的截图、化验和台账是只读现场原始资料；
- M5 协调值混合现场观测和 M2 潜变量先验，必须标为混合来源；
- M2、M3、M4 和 M6 的运行结果是合成模型结果，运行契约强制 `synthetic=true`；
- M2/M3/M4 的声明范围为 `engineering_simulation_only`；M6 为
  `engineering_validation_only`；
- 任一运行的 `data_origin`、版本和源文件指纹必须随结果保存，不能把模型预测写成现场实测。

## 7. 关键限制

### 7.1 无现场动态验证

当前只有弱时间对齐的单案例现场资料用于 M5 基准对齐，没有时间同步的现场动态输入—输出数据。
执行机构、传感器、热状态和库存响应的时间常数，以及冷凝和塔温响应幅值，仍是低可信局部工程初值。
M3/M4 场景通过只证明模型内部在既定假设下的数值、守恒和方向性行为，不证明现场动态精度。

### 7.2 “液位”是库存代理

M4 三个所谓液位分别是闪蒸罐、回流罐和塔底的 `当前质量库存 / 名义质量库存`。模型没有容器几何、
密度—高度关系或现场液位量程，因此这些变量不是米、毫米或百分比量程意义上的真实液位。
PI 输出是流量或热负荷命令，不是真实阀位。

### 7.3 M6 保护不是 SIS

M6 保护层只验证模型内的信号有效性、延迟、回差、锁存、复位、命令优先级和 PI 手动跟踪。
阈值、延迟和动作都是低可信合成验证包络，不是现场报警/联锁定值，也没有安全完整性等级、独立保护层
或硬件故障概率含义。它不能用于设计、验证、替代或绕过 SIS。

### 7.4 工程区间不是统计置信区间

M6 不确定度使用固定参考点的局部 Jacobian 和输入工程半宽形成 `engineering_parameter_envelope`。
它不是由重复样本估计的概率分布，不是标准差、置信区间、预测区间或风险概率。M5 的优化边界、
正则尺度、截图显示分辨率也都不能解释成统计 `1σ`。

### 7.5 局部适用域

动态和控制响应主要针对名义点附近约 `±5%` 的局部扰动。受限场景必须保留 `limited` 标签；
不支持的汽提蒸汽或动态含水请求必须在求解前 `rejected`。输入有限、结果守恒或数值收敛并不自动说明
该输入具有工程代表性。

## 8. 允许用途与禁止用途

允许在明确标注“工程合成仿真”的前提下用于：

- 离线教学、模型结构讨论和软件测试；
- 名义点附近的方向性比较与敏感性研究；
- 守恒、控制逻辑和异常场景的工程验证；
- 生成可追溯的合成样本供方法开发，但必须保留来源与限制标签。

禁止用于：

- 现场闭环控制、自动下发设定值或直接写入 DCS；
- SIS、联锁、报警或安全完整性等级的设计、验证、旁路或替代；
- 产品质量保证、化验替代、放行判定或操作许可；
- 设备极限、阀门行程、真实液位或保护定值的确认；
- 在线优化、实时优化、经济调度或绕过现有工艺/安全审批；
- 将 M5 单案例结果外推为其他原油、季节、负荷或装置状态的已验证精度。

## 9. 可追溯性与责任边界

每个有效运行目录由最后发布的 `manifest.json` 确认完整性，并记录请求、结果、有效输入、包内资源、
`source_fingerprints`、已安装源码树、版本、环境和全部产物的 SHA-256。`m5_overlay_version` 在版本谱系中
显式保留；Git commit/dirty 无法可靠发现时明确记为 `unavailable`，不代替强制的已安装源码树指纹。

reader 会拒绝缺失 manifest、路径越界、大小/哈希变化、多余或暂存文件，并交叉核对 request、result、
11 项输入、公共/底层/适用域状态、版本和来源指纹。哈希只能证明读取到的字节与合同一致，不能证明物理模型正确
或数据适合现场决策。

任何用于论文、报告或演示的结果都应同时披露：预设/请求、运行状态、`synthetic`、`data_origin`、
`claim_scope`、请求/结果/有效输入指纹、软件/模型/案例版本以及本模型卡的限制。发现输入来源变化、
守恒失败、未收敛、适用域拒绝、reader 篡改告警或文档与实现不一致时，应停止解释结果并保留原证据。
